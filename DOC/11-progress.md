# 11. 진행 기록

이 문서는 구현 이력, 검증 중 수정한 내용, 실제 실행 점검 결과, 남은 한계를 기록합니다. 기능별 사용법은 04~10 문서를 참고하세요.

## 1. 현재 상태

| 항목 | 상태 |
| --- | --- |
| 코어/컴포넌트 | 완료 |
| 데모 데이터/서버 | 완료 |
| 6개 데모 뷰 | 완료 |
| 문서 11종 + 문서 뷰어 | 완료 |
| 정적 검사(`npm run check`) | 통과 |
| Edge 헤드리스 실행 점검 | 통과 |

버전은 `1.0.0` 이며, 런타임 의존성과 빌드 도구는 없습니다. Node.js 는 데모 서버, JSON 생성, 정적 검사에만 사용합니다.

## 2. 구현 범위

### 2.1 코어

- `core/util.js`: DOM 헬퍼, 날짜/숫자, 경로, 검증, 옵션 정규화, 파일, 저장소, CSV
- `core/emitter.js`: `on/once/off/emit/destroy` 이벤트 이미터
- `core/ajax.js`: fetch 래퍼, 타임아웃/취소, JSON 파싱, 요청 로그, mock 폴백
- `core/skin.js`: 테마 10종, 모양 4종, 밀도 3종, localStorage, 사용자 등록, 피커

### 2.2 컴포넌트

- `editor/editor.js`: `contenteditable` 에디터, 서식/표/이미지, HTML 소스, 전체화면, 자동저장, `sanitizeHtml`
- `grid/grid.js`: sticky 헤더, 좌/우 고정 열, absolute 가상 스크롤, 정렬/검색/필터, 12종 셀 타입, 검증, 변경 추적, CSV
- `tree/tree.js`: 트라이스테이트 체크, cascade, 검색/하이라이트, 키보드, 추가/수정/삭제, 지연 로딩
- `layout/controls.js`: 31종 컨트롤 레지스트리와 `registerControl`
- `layout/layout.js`: 12컬럼 flow, `pos` absolute, 조건부 표시/비활성, 검증, 바인딩, 액션
- `app/app.js`: 메뉴 → 레이어 → 데이터 AJAX, 탭, 해시, 로딩/오류/재시도, AJAX 로그, 스킨 패널
- `webui.js`: 전역 `WUI` 와 named export 통합

### 2.3 스타일/데모/도구

- `src/css`: `tokens` → `base` → 컴포넌트 → `app` → `demo` 순서
- `src/data/seed.js`: 메뉴 6개, 레이어 6개, 데이터 5개, 트리/대시보드 데이터의 단일 소스
- `serve.mjs`: 정적 파일 + `/api/menu`, `/api/layers/:id`, `/api/data/:id`, `/api/tree`, `/api/submit`, `/api/action/:name`
- `tools/build-data.mjs`: `seed.js` → JSON
- `tools/build-docs.mjs`: `DOC/*.md` → `docs-data.js/json`
- `tools/check.mjs`: 모듈/내보내기/데이터/문서 정적 검사
- `tools/browser-check.mjs`: Edge CDP 실제 실행 점검

## 4. 검증 중 수정한 내용

### 4.1 레이아웃 메타의 필드 요소 누락

- 증상: 조건부 표시/비활성 갱신 시 `meta.el` 을 기준으로 필드 래퍼를 제어했지만, 메타에 `el` 이 없어 일부 상태 갱신이 어긋났습니다.
- 원인: 필드 메타 생성 시 `fieldEl` 만 넣고 `el` 별칭을 누락했습니다.
- 수정: `layout.js` 의 필드 메타에 `el: fieldEl` 을 추가해 표시/숨김과 오류 갱신이 같은 요소를 바라보게 했습니다.

### 4.2 스킨 피커 컨테이너 클래스 덮어쓰기

- 증상: 테마/모양 피커를 앱 사이드바에 붙였을 때 피커 루트의 기존 클래스가 사라져 레이아웃이 깨졌습니다.
- 원인: 피커 생성 시 `className = 'wui-swatches'` 처럼 기존 클래스를 덮어썼습니다.
- 수정: `classList.add(...)` 로 필요한 클래스만 추가하도록 변경했습니다.

### 4.3 데모 모듈 상대 경로

- 증상: 데모 페이지에서 일부 모듈 import 가 잘못된 상대 경로를 가리켜 로딩이 실패했습니다.
- 원인: `src/js/demo.js` 의 import 경로가 실제 폴더 깊이와 맞지 않았습니다.
- 수정: `../core/...`, `../editor/...`, `../layout/...` 기준으로 경로를 정리했습니다.

### 4.4 문서 정합성 수정

구현과 문서가 어긋난 부분도 함께 정리했습니다.

- `06-tree.md`: `addNode` 의 실제 시그니처를 `addNode(parentId, raw, index?)` 로 수정하고 예제 순서를 바로잡았습니다.
- `07-layout-json.md`: `props.maxLength` 가 입력 요소에 적용된다는 설명을 제거하고, `rules` 의 `maxLength` 검증으로 안내했습니다. 사용자 컨트롤 예제는 내부 상태(`current`)를 갱신하도록 수정했습니다.
- `08-menu-layer-ajax.md`: 실제로 사용하지 않는 `cache`, `statusBar` 를 예약 옵션으로 표시하고, 실제 동작하는 `keepTitle` 을 추가했습니다.
- `02-demo-guide.md`: `npm run check` 에 문서 동기화 검사가 포함된 뒤 검사 항목 6번이 실제 동작과 일치하도록 유지했습니다.

### 4.5 그리드 로딩 오버레이가 사라지지 않음

- 증상: 그리드 데이터를 다 불러온 뒤에도 하단(오버레이)의 "불러오는 중…" 메시지가 계속 남아 있었습니다.
- 원인: 로딩 요소는 `hidden` 속성으로 숨겼지만, `.wui-grid-loading { display: flex }` 규칙이 브라우저 기본 `[hidden] { display: none }` 보다 우선해 `hidden` 이 무시됐습니다.
- 수정: `base.css` 에 `[hidden] { display: none !important; }` 전역 규칙을 추가했습니다. 같은 원인으로 항상 보이던 에디터 이미지 도구 막대(`.wui-editor-imgbar`)도 함께 해결됩니다.
- 재발 방지: `tools/browser-check.mjs` 가 앱/데모 화면에서 `hidden` 속성을 가졌지만 계산된 `display` 가 `none` 이 아닌 요소 수를 세어 0 이 아니면 실패하도록 점검을 추가했습니다.

## 6. 남은 한계

### 에디터

- 서버 업로드가 내장되어 있지 않습니다. 실제 서비스에서는 `image.uploader` 를 제공해야 합니다.
- 업로더가 없으면 이미지가 data URL 로 본문에 들어가 HTML 이 커집니다.
- `document.execCommand` 기반이라 브라우저별 서식 결과가 조금 다릅니다.
- 표 셀 병합/분할, 이미지 리사이즈 핸들, 협업 편집, 변경 이력은 없습니다.

### 그리드

- 열 순서 드래그, 열 숨김, 그룹핑, 피벗은 없습니다.
- 행 높이는 균일해야 하며 자동 줄바꿈 행 높이는 지원하지 않습니다.
- 셀 병합은 없습니다.
- 서버 저장은 `save` 이벤트/`onSave` 에서 직접 구현해야 합니다.
- 매우 큰 데이터는 행 가상화로 렌더 비용을 줄이지만, 정렬/필터는 전체 데이터를 대상으로 합니다.

### 트리

- 노드 드래그 앤 드롭 이동은 없습니다.
- 가상 스크롤이 없어 노드 수가 매우 많으면 지연 로딩이 필요합니다.
- 범위 선택은 없고 `Ctrl/Cmd` 기반 다중 선택만 지원합니다.

### 레이아웃/앱

- 중첩 그룹(그룹 안의 그룹)은 지원하지 않습니다.
- `labelPosition`, `options.mode` 는 예약 옵션이며 실제 렌더는 스키마의 `mode` 와 상단 라벨을 따릅니다.
- 앱의 `cache`, `statusBar` 옵션은 예약 상태입니다. 열린 탭은 항상 유지되고 상태 바는 항상 표시됩니다.
- 메뉴/레이어의 `html` 컨트롤은 HTML 을 그대로 삽입하므로 신뢰된 JSON 에만 사용해야 합니다.
- 인증/권한, 서버 저장 정책, 파일 업로드 API 는 데모 범위에 포함되지 않습니다.

### 검증/운영

- 단위 테스트 프레임워크를 두지 않았습니다. 현재 검증은 정적 검사 + Edge CDP 실행 점검입니다.
- CDP 점검은 로컬 Edge 설치 경로에 의존합니다.
- 문서 뷰어의 Markdown 렌더러는 문서 작성에 필요한 범위(헤딩/목록/표/코드/인용/링크/이미지/인라인 서식)만 지원합니다. 각주, 수식, 중첩 인용 등은 지원하지 않습니다.
- 문서 내 검색은 제목/본문 전체 문자열 포함 여부를 사용하며, 전문 검색 인덱스는 없습니다.
